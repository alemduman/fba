# Битва флагов: автопостинг в Instagram

Этот репозиторий сам делает ролики «Битва флагов» и публикует их в ваш Instagram как Reels по расписанию.

**Как это работает.** В заданное время GitHub (бесплатно) открывает ваше приложение в браузере без экрана. Приложение подбирает страны и записывает ролик. Видео ненадолго выкладывается по публичной ссылке (GitHub Pages), потому что Instagram принимает видео только по ссылке. Затем ролик публикуется через официальный API Instagram, а в `state.json` записывается, что уже вышло: так страны не повторяются, а турнир идёт дальше.

Пароль от Instagram нигде не нужен. Доступ даёт **токен**: длинная строка, которую выдаёт Meta. Он хранится только в секретах GitHub, его не видно ни в файлах, ни в логах.

На настройку уйдёт около 30 минут. Нужен компьютер: с телефона загружать файлы на GitHub неудобно.

| Файл | Зачем |
|---|---|
| `app.html`, `mp4-muxer.js` | приложение «Битва флагов» |
| `config.json` | настройки: режим, страны, язык, турнир, расписание вкл/выкл |
| `state.json` | что уже опубликовано и где сейчас турнир (заполняется само) |
| `FLAGS.md` | все флаги и их коды |
| `scripts/` | программы, которые делают ролик и публикуют его |
| `.github/workflows/autopost.yml` | расписание и шаги запуска на GitHub |

## Шаг 1. Профессиональный аккаунт Instagram

API работает только с профессиональными аккаунтами («Автор» или «Бизнес»). Если аккаунт уже такой, пропустите шаг.

В приложении Instagram: профиль → ☰ → **Настройки и конфиденциальность → Тип аккаунта и инструменты → Переключиться на профессиональный аккаунт** → «Автор». Аккаунт должен быть открытым.

## Шаг 2. Приложение Meta, бизнес-портфолио и токен

Meta часто переименовывает кнопки. Если что-то выглядит иначе, ищите похожее по смыслу. Этот путь проверен на реальном интерфейсе (октябрь 2026).

1. Откройте [developers.facebook.com](https://developers.facebook.com), войдите через Facebook. **My Apps → Create App**, название любое (например `Flags Poster`), почта ваша.
2. В списке сценариев выберите **«Управление сообщениями и контентом в Instagram»** → **Далее**. Остальные шаги пройдите до конца («Требования не найдены» значит, что ничего заполнять не надо) → **Создать приложение**. Публиковать приложение и становиться «поставщиком технологий» не нужно.
3. Слева **«Сценарии использования»** → у сценария Instagram **«Настроить»** → в меню слева **API setup with Unified login**. Там нужно **бизнес-портфолио**: нажмите **«+ Бизнес-портфолио»** → **«Создать аккаунт»** и пройдите шаги Meta (название любое, например `Flags Battle`).
4. Подключите свой Instagram к портфолио: [business.facebook.com](https://business.facebook.com) → **Настройки** → **Аккаунты → Аккаунты Instagram → Добавить**, войдите в Instagram и разрешите доступ. В окне «…was added to the business portfolio» переключатель «Управлять пользователями» оставьте выключенным → **Готово**. Запишите числовой **ID аккаунта Instagram**: он виден в адресной строке как `selected_asset_id=17841…` (длинное число, начинается на 17841). Он понадобится в шаге 4.
5. В тех же настройках: **Пользователи → Системные пользователи → Добавить**. Название `flagbattle-poster`, роль **Админ** → **Создать системного пользователя**.
6. Нажмите **«Назначить объекты»** (Add assets) и дайте этому пользователю полный доступ к двум вещам: **приложению** (вкладка «Приложения», выберите Flags Poster) и **аккаунту Instagram** (вкладка «Аккаунты Instagram»).
7. Нажмите **«Создать токен»** (Generate token): выберите приложение **Flags Poster**, срок действия **«Никогда»** (если такого нет, выберите максимальный), разрешения: **`instagram_basic`** и **`instagram_content_publish`** (если есть `instagram_business_basic` и `instagram_business_content_publish`, отметьте и их) → **Создать токен** и скопируйте его. Сразу переходите к шагу 4 и вставьте токен в GitHub: после закрытия окна токен больше не показывается. Больше никуда его не отправляйте.

Режим приложения Development и проверку приложения (App Review) трогать не нужно: публиковать в собственный аккаунт можно и так.

## Шаг 3. Репозиторий на GitHub

1. Зарегистрируйтесь или войдите на [github.com](https://github.com).
2. Справа вверху **+ → New repository**. Name, например, `flag-battle-autopost`. Выберите **Public**: бесплатный GitHub Pages работает только в публичных репозиториях (для приватного нужен платный GitHub Pro). Остальное не трогайте → **Create repository**.
3. На странице пустого репозитория нажмите ссылку **uploading an existing file**.
4. Распакуйте архив и перетащите в окно браузера **содержимое** папки (всё, что внутри, а не саму папку), обязательно вместе со скрытой папкой `.github`:
   - Mac: в Finder нажмите **Cmd + Shift + .** (точка), чтобы увидеть скрытые папки;
   - Windows: папка `.github` видна как обычная.
5. Внизу **Commit changes**.
6. Проверьте, что в репозитории появилась папка `.github/workflows` с файлом `autopost.yml`. Если её нет (браузер не загрузил скрытую папку): **Add file → Create new file**, в поле имени напишите `.github/workflows/autopost.yml` (слеши сами создадут папки), вставьте содержимое файла `autopost.yml` из архива (откройте его любым текстовым редактором) → **Commit changes**.

## Шаг 4. Токен в секреты GitHub

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.

Создайте два секрета (кнопка **New repository secret**, потом **Add secret**):

| Name | Secret |
|---|---|
| `IG_TOKEN` | токен из шага 2 |
| `IG_USER_ID` | числовой ID аккаунта Instagram из шага 2 (начинается на 17841) |

После сохранения секрет нельзя посмотреть, только заменить. GitHub подставляет его в запуск и прячет в логах.

## Шаг 5. Включить GitHub Pages

**Settings → Pages → Build and deployment → Source: GitHub Actions**. Больше ничего не нужно.

## Шаг 6. Проверочный запуск, без публикации

1. Вкладка **Actions**. Если GitHub спрашивает про workflows, нажмите **I understand my workflows, go ahead and enable them**.
2. Слева **Flag Battle autopost** → справа **Run workflow** → галочка «Проверка: сделать видео, но НЕ публиковать» **включена** → зелёная кнопка **Run workflow**.
3. Через 5–10 минут у запуска появится зелёная галочка. Откройте его: на странице **Summary** будут страны, подпись и ссылка на видео. Посмотрите ролик по ссылке. Там же есть строка «Instagram: аккаунт @…, право на публикацию есть»: так проверка подтверждает, что токен рабочий и публиковать можно (сам ролик при этом не выходит). Если токен или ID неверные, запуск закончится красным крестиком с понятным пояснением.

## Шаг 7. Первая настоящая публикация

Снова **Run workflow**, но галочку «Проверка…» **снимите** → **Run workflow**. Через 5–10 минут ролик выйдет в Instagram, ссылка на него будет в **Summary** запуска.

## Шаг 8. Расписание

В `config.json` уже стоит `"autoPublish": true` и `"startDate": "2026-10-31"`: с 31 октября (по Баку) ролики выходят сами, **7 раз в день, каждые 2 часа, с 10:00 до 22:00**. GitHub иногда запускает задачи с опозданием на 5–30 минут, это нормально.

Пауза: поставьте `"autoPublish": false` (запуски по расписанию станут холостыми). Ручной запуск (**Run workflow**) работает всегда.

## Расписание

Время задаётся в `.github/workflows/autopost.yml`, строка `- cron: '7 6,8,10,12,14,16,18 * * *'`. Формат: минуты, часы **по UTC**, дальше звёздочки. Баку = UTC + 4, поэтому часы 6, 8, 10, 12, 14, 16, 18 по UTC — это 10:07, 12:07, … 22:07 по Баку. Минута `:07` выбрана специально: в начале часа у GitHub очередь, и запуски опаздывают сильнее.

Примеры: три ролика в день в 12:07, 16:07 и 20:07 по Баку: `- cron: '7 8,12,16 * * *'`. Только по будням: добавьте в конец `1-5` вместо последней звёздочки, то есть `'7 6,8,10,12,14,16,18 * * 1-5'`.

Instagram разрешает до 100 публикаций через API в сутки, так что 7 в день это с большим запасом. Дата, с которой запуски по расписанию начинаются, задаётся в `config.json` полем `startDate`.

## Настройки: `config.json`

Файл можно править прямо на GitHub: карандаш → правка → **Commit changes**. Следите за кавычками и запятыми: если в файле ошибка, запуск остановится и в логе будет написано, что не так.

| Поле | Что значит | Значения |
|---|---|---|
| `autoPublish` | публиковать по расписанию | `false` или `true` |
| `startDate`, `timezone` | с какой даты (по этому часовому поясу) начинаются запуски по расписанию | `"2026-10-31"`, `"Asia/Baku"`; пусто: сразу |
| `language` | язык надписей в ролике и подписи | `en`, `ru`, `uk`, `tr`, `az`, `es`, `pt`, `de`, `fr`, `it`, `ar` |
| `mode` | режим боя | см. таблицу ниже. Несколько через запятую, например `"lines,roulette"`: каждый раз случайный из них. `"random"`: любой |
| `speed` | скорость шаров | 60–700 |
| `lines` | линий в начале (только «Битва линий») | 5–80 |
| `ramp` | разгон к концу (только «Битва линий») | 1–8 |
| `length` | длина ролика в секундах | `"20-29"` (по умолчанию) |
| `maxSeconds` | жёсткий потолок длины: слишком длинная партия отбрасывается и подбирается заново | `30` |
| `recordBitrate` | битрейт записи в браузере (чем выше, тем лучше исходник) | `20000000` |
| `music` | мелодия | `auto` (случайная), `orig`, `dark`, `phonk`, `funk`, `thriller`, `dnb`, `edm` |
| `sound` | звук | `all` (музыка и эффекты), `sfx` (только эффекты), `off` |
| `watermark` | ваш ник внизу видео | например `"@flagbattle"`; пусто, если ник не нужен |
| `ad` | рекламный баннер сверху | `off`, `musor` (Musor Drop), `vpn` (444 VPN) |
| `countriesPerVideo` | сколько флагов в ролике | `[3, 3]`; `[2, 3]` значит от 2 до 3, максимум 8 |
| `picks` | умный подбор стран (см. ниже). `null`: не использовать, тогда страны берутся из `groups` | |
| `coverStyle` | обложка Reels | `"who"` (крупные флаги и «WHO WINS?») или `"frame"` (кадр из ролика) |
| `groups` | откуда брать флаги, если `picks` выключен | `["eu"]` Европа, `["countries"]` все страны мира, можно несколько: `["eu", "cis"]`. Все группы и коды есть в `FLAGS.md` |
| `include` | добавить отдельные флаги | например `["az", "tr"]` |
| `exclude` | никогда не брать | например `["ru"]` |
| `tournament` | турнир | см. ниже |
| `cover` | делать обложку | `true` или `false` |
| `shareToFeed` | показывать ролик и в сетке профиля | `true` или `false` |
| `extraHashtags` | свои хэштеги | например `["geography"]`. Instagram разрешает не больше 5 хэштегов, поэтому свои ставятся первыми, а оставшиеся места занимают хэштеги приложения |
| `login` | какой токен используется | `"unified"` (токен системного пользователя, по умолчанию) или `"instagram"` (токен входа через Instagram, продлевается сам) |
| `apiVersion` | версия API Instagram | не трогать |

| `mode` | Режим |
|---|---|
| `lines` | ⚔️ Битва линий |
| `pegs` | 📍 Падение по палочкам |
| `maze` | 🧩 Лабиринт с воротами |
| `spin` | 🌀 Горка с вертушками |
| `funnel` | 🎯 Воронка с кольцами |
| `slope` | ⛷️ Склон с трамплинами |
| `roulette` | 🎰 Рулетка |

Страны выбираются случайно, и один и тот же набор не повторяется в пределах последних 60 роликов.

## Подбор стран (`picks`)

Чтобы ролики заходили, страны не берутся наугад из всех флагов. В `config.json`, блок `picks`:

- `sets`: готовые **тематические тройки** с соперничеством или общей историей (Германия, Франция, Италия; Бразилия, Аргентина, Уругвай; США, Китай, Россия; Турция, Греция, Болгария; и т. д.). Можно добавлять свои: `["код", "код", "код"]`.
- `setChance`: какую долю роликов делать из готовых троек (`0.45` = около 45%).
- `europe` и `world`: списки **популярных стран** для остальных роликов. `europeShare` (`0.65`) задаёт, как часто каждая страна берётся из европейского списка.
- `pairs`: пары-соперники для четвертьфиналов турнира (включая Россию и Украину, Армению и Азербайджан, Индию и Пакистан, обе Кореи, Израиль и Иран).
- `neverTogether`: пары, которые не должны попадать вместе в случайные ролики. Сейчас список пустой, то есть ограничений нет; чтобы что-то исключить, добавьте пару вида `["ru", "ua"]`.

Только суверенные страны: регионы, штаты США, субъекты и особые флаги в списках не используются. Одинаковые тройки не повторяются в пределах последних 60 роликов. Коды всех флагов есть в `FLAGS.md`. Проверка на 700 роликах: около 46% тематических, около 57% европейских слотов.

## Турнир

```json
"tournament": { "enabled": true, "weekday": "thu", "size": 8, "teams": "rivals", "length": "18-25", "name": "", "outro": true }
```

Раз в неделю, в день `weekday` (сейчас четверг, по Баку), вместо обычных роликов проходит **турнир на 8 команд**: 4 четвертьфинала, 2 полуфинала и финал. Это ровно 7 матчей, то есть все 7 слотов дня: 10:07, 12:07, 14:07 и 16:07 четвертьфиналы, 18:07 и 20:07 полуфиналы, 22:07 финал. В каждом матче 2 страны, победитель случайный, в конце ролика 3 секунды турнирной сетки. Подпись сама пишет стадию («Полуфинал 1/2», «Финал»), а на обложке под «WHO WINS?» стоит название турнира и стадия.

- `enabled`: `false` выключает турниры совсем.
- `weekday`: день недели турнира: `mon`, `tue`, `wed`, `thu`, `fri`, `sat`, `sun`. Пусто: турниры идут подряд без обычных роликов.
- `size`: 4, 8 или 16 участников (7 роликов в день получается только при 8).
- `teams`: `"rivals"` (четвертьфиналы между соперниками из `picks.pairs`: Германия–Франция, Бразилия–Аргентина и т. д.) или `"random"` (случайные популярные страны).
- `length`: длина матча без сетки. Вместе с 3 секундами сетки ролик остаётся короче 30 секунд.
- `name`: название. Пусто: автоматическое (`WORLD FLAG CUP`, а если все участники европейские, `EURO FLAG CUP`).
- `outro`: показывать сетку в конце каждого ролика.

Ход турнира хранится в `state.json`. Если публикация матча не удалась, он сыграется заново при следующем запуске, а если турнир не закончился за день, он дойдёт до финала в следующих слотах. Чтобы сбросить турнир, поставьте в `state.json` `"tournament": null`.

## YouTube Shorts (по желанию)

Тот же ролик после Instagram загружается на YouTube. Включается тремя секретами: `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`. Без них шаг пропускается.

1. console.cloud.google.com → создать проект → «APIs & Services» → включить **YouTube Data API v3**.
2. «OAuth consent screen» → External → заполнить название и почту → добавить scope `youtube.upload` → **Publish app (In production)**, иначе токен живёт 7 дней.
3. «Credentials» → Create credentials → OAuth client ID → тип **Web application**, Authorized redirect URI: `https://developers.google.com/oauthplayground`. Скопировать Client ID и Client secret.
4. developers.google.com/oauthplayground → шестерёнка → «Use your own OAuth credentials» → вставить их → слева ввести scope `https://www.googleapis.com/auth/youtube.upload` → Authorize APIs → войти в аккаунт канала → Exchange authorization code for tokens → скопировать **Refresh token**.
5. Добавить три секрета в GitHub. Запустить «Проверка» вручную: в логе будет «Канал YouTube: …».

Ограничения: квота YouTube API по умолчанию около 6 загрузок в сутки; пока проект не прошёл аудит Google, ролики могут принудительно становиться приватными. Настройки в `config.json` → `youtube` (`enabled`, `privacy`, `category`, `fromHour`: с какого часа по Баку выкладывать на YouTube; сейчас 12, поэтому ролик 10:07 идёт только в Instagram, а остальные шесть и туда, и туда).

## Защита от опоздавших запусков

GitHub иногда запускает расписание с задержкой в часы. В `config.json` → `schedule`: `hours` (часы слотов по Баку), `minute`, `maxDelayMinutes` (90). Если запуск пришёл позже, чем через 90 минут после ближайшего слота, он пропускается и ролик не выходит.

## Токен и его срок

Токен системного пользователя, созданный со сроком «Никогда», продлевать не нужно. Если Meta не дала такой срок, токен живёт 60 дней: за неделю до конца создайте новый (шаг 2, пункт 7) и замените секрет `IG_TOKEN` (**Settings → Secrets and variables → Actions → IG_TOKEN → Update**). Когда токен истечёт, запуск остановится с ошибкой `код 190`, и вам придёт письмо.

Если у вас обычный токен входа через Instagram (60 дней, продлевается), поставьте в `config.json` `"login": "instagram"`: тогда скрипт будет продлевать его сам, а `IG_USER_ID` станет необязательным. Для этого токена нужен секрет `GH_PAT` (fine-grained токен GitHub только для этого репозитория с правом **Secrets: Read and write**), чтобы новая строка токена сохранялась сама.

## Если что-то не так

Если запуск не удался, GitHub пришлёт письмо, а у запуска будет красный крестик. Откройте его, нажмите на шаг с ошибкой и найдите строку с ❌: там по-русски написано, что случилось.

| Что видно | Что делать |
|---|---|
| ошибка в шаге `configure-pages` (`Get Pages site failed`) | не включён GitHub Pages, шаг 5 |
| `Нет секрета IG_TOKEN` | шаг 4 |
| `Нет секрета IG_USER_ID` | добавьте секрет с числовым ID аккаунта (шаг 4) |
| `(код 190)` | токен истёк или вставлен с ошибкой: создайте новый (шаг 2, пункт 7) и обновите секрет `IG_TOKEN` |

## Безопасность

- Токен хранится только в секретах GitHub. Не вставляйте его в файлы, Issues и комментарии и не отправляйте в чаты.
- Токен системного пользователя с правом публикации даёт возможность выкладывать посты в ваш аккаунт, поэтому относитесь к нему как к паролю. Отозвать его можно в Business Settings (системный пользователь → токены → отозвать) или удалением системного пользователя.
- Репозиторий публичный: код, настройки и история публикаций видны всем, у кого есть ссылка. Логи запусков тоже публичные, но скрипты токен не печатают, а GitHub дополнительно заменяет секреты звёздочками.
- Видео лежит по публичной ссылке только до следующего запуска: каждый запуск заменяет сайт новым роликом.
- Отключить доступ можно в любой момент: удалите секрет `IG_TOKEN`, отзовите токен или удалите системного пользователя в Business Settings, или удалите приложение на developers.facebook.com.

## Обновление приложения

Когда приложение «Битва флагов» обновляется, замените `app.html` в репозитории: **Add file → Upload files** → перетащите новый файл с тем же именем → **Commit changes**.
